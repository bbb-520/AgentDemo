## 工具调用流式截断根治 + 架构解耦（agentDemo1_0）


- **根因**：qwen-turbo 流式输出 tool_calls 时 arguments 增量流中途夭折（半截 JSON）。旧架构在流式路径上打补丁（合并/判截断/非流式恢复），治标。
- **方案（v4 两阶段架构）**：工具决策轮一律非流式 `chatModel.call()`（参数必完整）；答案 12 字/30ms 分块回放；非法参数作为 ToolResponse 回传模型自愈（上限 6 轮）。删除 recoverTruncatedTurn/mergeCompleteToolCalls 约 200 行补丁。

- **升级**：Spring AI 1.0.0-M6 → 1.0.5（spring-ai-core 拆分为 spring-ai-client-chat + spring-ai-model；ChatMemory.get 单参；MessageWindowChatMemory + InMemoryChatMemoryRepository）。
- **两个坑（已加回归测试/注释）**：① `AopUtils.getTargetClass(Object)` 收实例不收 Class，误传 Class 得 java.lang.Class，导致工具扫描为 0；② WebClient `.uri(String)` 会把已编码 URI 当模板二次编码，中文参数必须传 java.net.URI。

## 会话记忆 HELP 文档编写（agentDemo1_0）

- **产出**：根目录 `HELP-会话记忆.md`（15 章）：速览表 / 链路图 / 组件清单 / 会话键规则 / 存储层 / 双路径读写时序 / 中断回写 / 历史查询 / 多轮记忆快照 / 设计权衡 / 9 条风险清单 / 5 个改造示例（Redis 持久化、中断回写修复、窗口配置化、按用户隔离、摘要压缩）/ 验证与排查 / FAQ / 源码索引。
- **核实方式（重要）**：不靠记忆写文档，用 `/d/jdk21/bin/javap.exe -p -c` 反编译本地 `~/.m2` 的 spring-ai 1.0.5 jar 逐条核对（注意：javap 的 -classpath 必须用 `C:/...` 形式，`/c/...` 会 NoSuchFileException）。
- **核对结论**：
  - `ChatMemory.CONVERSATION_ID = "chat_memory_conversation_id"`，`DEFAULT_CONVERSATION_ID = "default"`。
  - `MessageChatMemoryAdvisor.before()`：取历史 → 历史插到 Prompt 指令**前面** → `add(userMessage)`（**先写 user 再发模型**）；`after()` 写响应的 assistant 消息。
  - `MessageWindowChatMemory.process(已有, 新增)`：已有 + 新增拼接；若新增含新的 SystemMessage 则丢弃旧 SystemMessage；超 `maxMessages` 时从最早的非 System 消息开始删（System 永不删）；`saveAll` 整段覆盖写。本项目入库只有 user/assistant，故等价于「保留最近 50 条」。
- **流式路径为何绕过 Advisor**：需逐轮直播事件（TOOL_CALL_*）+ 手动工具循环（`internalToolExecutionEnabled(false)` 是协议级要求）+ 答案分块回放；代价是记忆读写退化为手写（`loadConversationContext` 读 / `finalAnswerFlow` 写 user+assistant，工具中间消息不入库）。
- **已记录的 2 个真实缺陷**（文档 §7.3，附修复思路）：中断发生在工具阶段 → 记忆留下无 user 的孤儿 assistant；中断发生在回放阶段 → 完整答案 + 片段前缀两条 assistant。根因是流式路径「最后才写 user+assistant」而 Advisor 是「先写 user」。

## 修复：Lettuce 连接池缺 commons-pool2 导致启动失败（agentDemo1_0）

- **现象**：应用启动报 `NoClassDefFoundError: org/apache/commons/pool2/impl/GenericObjectPoolConfig`，依赖链 redisConnectionFactory → stringRedisTemplate → RedisChatMemoryRepository → agentRunner 全部创建失败（ApplicationContext 启动中止）。
- **根因**：`spring-boot-starter-data-redis` **不传递引入 commons-pool2**（optional 依赖），而 application.yml 配了 `spring.data.redis.lettuce.pool.enabled=true`，LettucePoolingClientConfiguration 构造时需要 `GenericObjectPoolConfig`。
- **修复**：pom 加 `org.apache.commons:commons-pool2`（版本由 spring-boot-starter-parent 管理，无需写 version）。本地仓库已有 2.12.1，离线编译通过。
- **替代方案**：不想加依赖就把 yml 的 `lettuce.pool.enabled` 设为 false 或删掉 lettuce 段（本地单机 Redis 无池也够用）。
