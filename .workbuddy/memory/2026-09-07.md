## AI 装配重构：LlmConfig → AiConfiguration（agentDemo1_0）

- **新文件**：`config/OpenAiProperties`（@ConfigurationProperties prefix=spring.ai.openai，绑定 yml 既有段；默认选项属性化）+ `config/AiConfiguration`（取代并删除 LlmConfig，集中 5 个 Bean：chatMemory / systemPrompt / qwenChatModel / agentAdvisorChain(List<Advisor>) / qwenChatClient）。
- **AgentRunner**：改 @RequiredArgsConstructor 注入 Bean；删除构造器 @Value 读 classpath:system_prompt（上移为 AiConfiguration 的 systemPrompt Bean，启动期 fail-fast）；同步 chat() 不再重复 .system()/.tools()，吃满 ChatClient default*；流式手动循环保留（逐轮事件+token 汇总+中间轮不入库与 MemoryAdvisor 冲突），历史装载抽 loadConversationContext() 显式复刻 advisor 语义。测试构造器签名未变，AgentRunnerTest 零改动。
- **坑**：ChatClient.Builder.defaultTools(Object...) 只收「含 @Tool 方法的对象」，传 ToolCallback 报 "No @Tool annotated methods found...use .toolCallbacks()"；ToolCallback 必须走 `defaultToolCallbacks(List<ToolCallback>)`。
- **验证**：离线 mvn 22 测试全绿（原 19 + 新 AiConfigurationTest 3）；SSE 协议/API 未变。文档：docs/CHANGELOG_2026-09-07_AI装配重构AiConfiguration.md。

## 工具调用流式截断根治 + 架构解耦（agentDemo1_0）


- **根因**：qwen-turbo 流式输出 tool_calls 时 arguments 增量流中途夭折（半截 JSON）。旧架构在流式路径上打补丁（合并/判截断/非流式恢复），治标。
- **方案（v4 两阶段架构）**：工具决策轮一律非流式 `chatModel.call()`（参数必完整）；答案 12 字/30ms 分块回放；非法参数作为 ToolResponse 回传模型自愈（上限 6 轮）。删除 recoverTruncatedTurn/mergeCompleteToolCalls 约 200 行补丁。
- **解耦**：`config/ToolConfig` 自动扫描 @Tool Bean 注册 ToolCallback（新增工具零接线）；天气数据源抽象 `WeatherProvider` 责任链，Open-Meteo（@Order 1，免费无 Key）首选 + Tavily（@Order 2）兜底，weatherTool 只依赖 WeatherService。
- **升级**：Spring AI 1.0.0-M6 → 1.0.5（spring-ai-core 拆分为 spring-ai-client-chat + spring-ai-model；ChatMemory.get 单参；MessageWindowChatMemory + InMemoryChatMemoryRepository）。
- **两个坑（已加回归测试/注释）**：① `AopUtils.getTargetClass(Object)` 收实例不收 Class，误传 Class 得 java.lang.Class，导致工具扫描为 0；② WebClient `.uri(String)` 会把已编码 URI 当模板二次编码，中文参数必须传 java.net.URI。
- **验证**：19 测试全绿；端到端北京天气/杭州两日游（getWeather→getAttraction 多工具链）无失败卡片；Open-Meteo 结构化中文实况命中。
- **文档**：`docs/CHANGELOG_2026-09-07_工具调用流式截断根治与架构解耦.md`（含新增工具/数据源指南）。
- SSE 事件协议 1001~1010 未变，前端零改动。

## 工具包抽取收尾：common.utils 从 tjxt-ai 移植并替换自创方法（agentDemo1_0）

- **背景**：下午 14:55 左右曾有一轮中断的移植尝试（已把 tjxt-ai tj-common 的 utils 复制/改造为 `common/utils` 20 个类并引入 hutool-all 5.8.32），但**未验证编译**、未写记忆即中断；基线编译报 NumberUtils 2 处错误。
- **修复（本次完成）**：
  - `NumberUtils`：删除自定义 `parseInt/parseLong(String)`（返回 Integer/Long 与 hutool 继承的 int/long 静态方法冲突，"无法隐藏"编译错误）；语义回落为 hutool `NumberUtil` 继承实现。
  - `SPELUtils`：清理残留的 `main()` 演示 + 内嵌 User + lombok @Data 依赖。
  - `CollUtils.joinIgnoreNull`：修复未使用传入分隔符、硬编码 "," 的潜在 bug（用 conjunction 拼接并整段删除尾部）。
  - `StringUtils`：新增 `truncate(String,int)`（超长加"…(已截断)"），承载 AgentRunner 原私有方法。
- **自创方法替换**：ChatController 的 `answer==null?"":answer` → `StringUtils.toString`；AgentRunner 私有 `truncate` 删除改用 `StringUtils.truncate`，`text!=null&&!isEmpty` → `StringUtils.isNotEmpty`（3 处）；ChatServiceImpl 同理。
- **结论**：业务代码不再持有手写 isBlank/trim/toString/截断工具，统一走 `common.utils`；工具包 20 个类与 tjxt 对齐（剔除 servlet/mybatis 相关不适用项）。
- **验证**：离线 mvn（classworlds 启动 + `-o`）19 测试全绿（AgentRunnerTest 事件序列含 isCompleteToolCall 脏数据过滤、ChatServiceImplTest、ToolConfigTest、应用上下文）。
