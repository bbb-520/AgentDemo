## agentDemo1_0 SSE 事件流重构（完整 Agent 直播）

**背景/结论**：Spring AI 1.0.0-M6 中 `ChatClient.stream()`/`ChatModel.stream()`（默认开启内部工具执行）
会在内部消费「工具调用决策」分片并自动循环执行工具，下游拿不到工具阶段 → 无法直播。
故重构为 AgentRunner **自行驱动工具循环**。

**改动文件**：
- `enums/ChatEventTypeEnum.java`：新增 TOOL_CALL_STARTED(1005)/TOOL_CALL_RESULT(1006)/REASONING(1007)/TOOL_CALL_FAILED(1008)/USAGE(1009)/SESSION_INFO(1010)。
- `agent/AgentRunner.java`：`stream()` 改为返回 `Flux<ChatEventVO>`，手动工具循环：
  - 每轮 `chatModel.stream(Prompt)` + `OpenAiChatOptions.internalToolExecutionEnabled(false)`；
  - 文本流按「思考：」行剥离为 REASONING（增量分类器 `ReasoningSplitter`，行首最多暂存 3 字符判定，正文零延迟放行），其余为 DATA；
  - 轮末检测 `AssistantMessage.getToolCalls()` → 执行 `ToolCallback`（阻塞调用 `.subscribeOn(boundedElastic)`）→ TOOL_CALL_STARTED/RESULT/FAILED，工具失败不回传错误继续兜底；
  - 轮次上限 MAX_TOOL_ROUNDS=6；跨轮 usage 覆盖式记录、轮末累加，流尾发 USAGE；
  - 记忆语义：首轮装载 system+历史+user，最终轮回写 user+assistant（不存中间工具消息）；
  - `chat()`（同步）仍走 ChatClient+记忆顾问，`tools(List<ToolCallback>)` 复用同一批回调。
- `resources/system_prompt`：诱导模型调用工具前先输出「思考：」行。
- `config/LlmConfig.java`：拆出 `OpenAiChatModel` Bean + `List<ToolCallback>` Bean（注意 provider 必须用具体类 `MethodToolCallbackProvider` 才能取到 `ToolCallback[]`，接口只会看到 FunctionCallback[]）。
- `service/impl/ChatServiceImpl.java`：事件原样透传不过滤（保留 null eventData 事件），仅维护 GENERATING 标记 + 尾部 STOP + onErrorResume→ERROR。
- 测试：新增 `agent/AgentRunnerTest`（3 用例），`ChatServiceImplTest` 增至 10 用例（新透传用例）。

**验证**：`mvn -o test` 全绿 14/14（含 Spring 上下文加载测试）。

**关键 API（M6 备忘）**：`AssistantMessage.ToolCall` 是 record(id,type,name,arguments)；`ChatResponse.hasToolCalls()`；
`ChatResponseMetadata.builder().usage()`；`ToolResponseMessage.ToolResponse(id,name,responseData)`；`ChatMemory.add(String,List<Message>)` 有重载（verify 时要用 typed ArgumentMatcher）。
